# 로맨스 거절 메커니즘 조사 (2026-11-01)

상태: 권장안대로 구현했다 (`src/game/romanceAcceptance.ts`). 쌍별 고정 끌림은 호불호로 대체해 넣지 않았다. 사귀자 기본값은 52%다. 수치는 측정값으로 표시한 것 외에는 시작값이며 플레이로 맞춰야 한다.

## 1. 현재 동작

`Game.socialOutcome`(`src/game/game.ts`)이 한 번의 점수로 결과를 정한다.

`점수 = 분위기 + 우정 구간 + 로맨스 구간 + 말 건 쪽의 카리스마·감정 + 상대 감정 + 특성 + 난수(±4)`

- `점수 ≤ social.fail`이면 실패(거절), `점수 ≥ social.great`면 대성공, 나머지는 성공이다.
- 기준값: 추파 -5/+15, 사귀자 -10/+10, 청혼 -10/+15.
- 거절 결과는 이미 있다. 로맨스 감소와 `rejected` 버프가 붙는다.

### 측정: 상대 감정별 거절률 (각 조건 3,000회, 카리스마 0)

| 행동 / 우정·로맨스 | 보통·기쁨·스트레스 | 슬픔 | 화남 |
|---|---|---|---|
| 추파 0 / 0 | 0% | 100% | 100% |
| 추파 30 / 40 | 0% | 38% | 100% |
| 사귀자 30 / 40 (메뉴가 열리는 최소 조건) | 0% | 0% | 76% |
| 사귀자 50 / 60 | 0% | 0% | 0% |
| 청혼 50 / 60 | 0% | 0% | 0% |

`propose`와 `askPartner`의 메뉴 조건을 벗어난 값은 표에서 뺐다. 전체 측정에서 나온 결론은 다음과 같다.

- **상대가 슬프거나 화나지 않으면 거절은 사실상 일어나지 않는다.**
- 같은 말을 세 번 연속하면 무조건 실패하는 지루함 규칙은 별도로 있다.
- 조건을 갖춘 뒤에는 상대가 누구든 결과가 같다. 점수에 **상대의 의사**가 없다.
- 상대 특성은 점수에 쓰이지 않는다. 특성 보너스는 말 건 쪽 것만 더한다.
- 문턱값 방식이라 확률 구간이 ±4로 좁고, 조건에 따라 0% 아니면 100%로 갈린다.

## 2. 참고 게임 자료 (`docs/ref-game/03`, `docs/ref-game/04`)

- 결과는 점수 문턱을 통과한 묶음들 중에서 **가중치 추첨**을 한다. 문턱 하나로 확정하지 않는다.
- 사귀자: 로맨스 30 이상. 점수 10 이상이면 성공 묶음 w5, 25 이하면 실패 w1, -15 이하면 실패 w3, 그 밖은 기본 성공.
- 청혼: 점수 25 이상이면 성공 w5, 15 이하면 실패 w2, -15 이하면 실패 w3.
- 약속을 꺼리는 특성(CommitmentIssues)은 사귀자 45 이하, 청혼 55 이하에서 실패 w6.
- 점수에 대상의 감정, 막 이별했는지, 대화 분위기 등이 들어간다.
- 추파 메뉴에는 성적 지향 호환 검사가 있다.
- 기록되지 않은 것: 참고 게임 기본 튜닝에서 개인별 호감 궁합을 다루는 부분. 후속 확장에 끌림 시스템이 있는 것으로 기억하지만 이 저장소 자료에는 없고 확인하지 않았다.

정리하면, 이 게임의 현재 구조는 참고 게임에서 **문턱 + 가중치 추첨**의 추첨을 뺀 형태다. 또 참고 게임의 특성 기반 거절도 빠져 있다.

## 3. 제안: 상대의 마음 점수 + 확률 판정

단계가 올라갈수록 어려운 **상대 쪽 판정**을 하나 추가한다. 적용 대상은 추파(가벼운 판정), 사귀자, 청혼이다. 애정표현은 이미 연인이므로 지금처럼 기분으로만 거절한다.

`수락 확률 = 단계 기본값 + 관계 + 궁합 + 상대 상태 + 말 건 쪽 + 이력` (5%~95%로 제한)

| 항목 | 내용 | 시작값 제안 |
|---|---|---|
| 단계 기본값 | 추파 / 사귀자 / 청혼 | 75% / 50% / 45% |
| 관계 | 로맨스가 메뉴 조건을 넘은 만큼, 우정 | 넘은 5점당 +3%, 상한 +25% / 우정 50 이상 +5%, 70 이상 +10% |
| 상대의 호불호: 사람 유형 | 상대가 좋아하는/싫어하는 유형(`people_*`)에 말 건 쪽 특성이 해당 (`peopleKindsOf`) | 좋아함 +12% / 싫어함 -15% |
| 상대의 호불호: 연애 이야기 | 상대의 `topic_romance`, 스킨십은 `topic_touch` | 좋아함 +8% / 싫어함 -12% |
| 취향 궁합 | 둘 다 좋아하는 활동 / 한쪽이 좋아하는 것을 다른 쪽이 싫어함 | 항목당 +3% / -4% |
| 호불호 합계 상한 | 위 세 줄 합계 | ±25% |
| 끌림(쌍마다 고정) | id 쌍에서 만든 고정값. 사람마다 맞는 상대가 다름 | -10~+10% |
| 상대 상태 | 감정 | 설렘 +10, 기쁨 +5, 스트레스·불편 -10, 슬픔 -20, 화남 -35 |
| 상대 특성 | 깊은 관계 회피, 낭만주의자 등 | 사귀자·청혼 -15 / +10 |
| 말 건 쪽 | 카리스마, 지금 데이트 중 | 레벨당 +1.5%, 데이트 +10% |
| 이력 | 최근 싸움·앙심, 최근 거절 | 앙심 -20, 재시도 간격 중에는 시도 불가 |

### 거절의 결과 (단계별)

| 단계 | 결과 | 재시도 |
|---|---|---|
| 추파 | 어색함, 로맨스 소폭 감소 | 바로 가능(지루함 규칙 유지) |
| 사귀자 | `rejected`, 로맨스 중간 감소, "아직은 친구로 지내고 싶대요" | 게임 시간 2일 후 |
| 청혼 | `rejected`, 로맨스 감소. 연인 관계는 유지 | 게임 시간 3일 후 |

- 재시도 간격은 함께 살기 거절의 `moveInRefusedUntil`과 같은 방식으로 저장한다.
- 메뉴에 확률을 숫자로 보여 주지 않는다. 상대를 알아 갈수록 `dwellerKnowledge`로 "나를 좋아하는 것 같아요" 같은 힌트를 준다.
- 사귀자 시도는 이미 있는 거절 두려움(`rejection`) 시스템에 그대로 연결된다.

### 구현 범위

1. `src/game/romanceAcceptance.ts`에 순수 함수로 작성하고 테스트로 단계·상황별 확률표를 고정한다.
2. `socialOutcome`에서 해당 소셜만 이 판정을 먼저 거친다. 다른 소셜의 점수 체계는 건드리지 않는다.
3. 메시지·재시도 간격을 추가한다.
4. 자동 행동 쪽 영향을 확인한다. `askPartner`, `propose`는 `autonomous: false`라 플레이어 선택에서만 발생하고, 추파는 자율 행동에도 적용된다.

## 3-1. NPC 호불호 배정 (구현됨)

`randomPreferences(rng, { traits, age, skill })`: 좋아하는 것 4개(활동 2, 주제 1, 사람 유형 1), 싫어하는 것 2~3개(활동 1, 사람 유형 1, 때로 하나 더). 특성·직업 스킬·나이로 가중치, 자기와 같은 유형을 좋아할 확률 60%, 연애 태도는 낭만주의자·깊은 관계 회피에서 파생하고 그 외 25%. 기존 NPC의 호불호는 유지.

## 4. 정해야 할 것

1. 평균 난이도: 조건만 겨우 갖춘 상태의 사귀자 수락률. 제안 약 50~60%.
2. 쌍마다 고정된 끌림을 넣을지. 넣으면 아무리 노력해도 어려운 상대가 생긴다. 제안은 ±10%로 작게 넣어 절대 불가능한 상대는 없게 한다.
3. 같이 사는 가족끼리(둘 다 플레이어 캐릭터)도 거절이 나올지. 제안: 동일하게 적용.
